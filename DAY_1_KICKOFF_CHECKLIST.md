# Day 1 Kickoff Checklist

## Purpose
This is the execution checklist for the first day of the 30-day internal pilot.

The public launch switch remains OFF.
The internal pilot switch remains ON only for approved pilot users.

---

## 1. Pilot start confirmation
- [ ] Public launch switch is OFF
- [ ] Internal pilot switch is ON
- [ ] Pilot start date recorded: ____________________
- [ ] Pilot owner team notified
- [ ] All required stakeholders are present or notified

## 2. User access control
- [ ] Approved pilot users list is complete
- [ ] User roles are assigned correctly
- [ ] Admin users are identified separately from standard users
- [ ] Restricted users are blocked from admin functions
- [ ] Unauthorized access test is scheduled
- [ ] Access exceptions are tracked

## 3. Authentication and identity checks
- [ ] Login flow tested for each role
- [ ] Logout flow tested
- [ ] Session expiry is reviewed
- [ ] Access token / auth state is verified where applicable
- [ ] Audit events for sign-in and sign-out are enabled

## 4. Dashboard and visibility checks
- [ ] Dashboard loads without critical errors
- [ ] User role sees only role-appropriate data
- [ ] No stale values or missing states are visible
- [ ] Grid data is visible and consistent
- [ ] Worker data is visible and consistent
- [ ] Treasury data is visible and safe for monitoring only
- [ ] Audit or system status panels are working

## 5. Financial guardrails
- [ ] Treasury observation remains read-only
- [ ] No automatic member-balance crediting is active
- [ ] No payout or settlement process is active outside approved controls
- [ ] Finance owner has reviewed the current guardrails
- [ ] Compliance reviewer has reviewed the financial posture
- [ ] Any financial exception is documented and approved

## 6. AI worker and grid controls
- [ ] AI worker list is present and readable
- [ ] Grid state displays correctly
- [ ] Worker assignment does not activate settlement logic
- [ ] Task flow is in pilot-safe mode
- [ ] All activity is logged for audit review

## 7. Monitoring and incident response
- [ ] Monitoring is active
- [ ] Support channels are live
- [ ] Incident reporting route is confirmed
- [ ] Freeze / pause command path is known
- [ ] Founder / Super Admin escalation path is active

## 8. Day 1 risk review
- [ ] No critical blocker identified
- [ ] No critical security or financial gap identified
- [ ] No material access control issue identified
- [ ] If issues exist, they are logged with owners and remediation actions

## 9. Day 1 sign-off
- Product owner: ____________________
- Engineering lead: ____________________
- Operations lead: ____________________
- Finance owner: ____________________
- Compliance reviewer: ____________________
- Founder / Super Admin: ____________________

## 10. Day 1 outcome
- [ ] Proceed to Day 2 testing
- [ ] Pause pilot due to issue(s)
- [ ] Escalate to leadership for review
